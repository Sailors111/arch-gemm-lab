# arch-gemm-lab

《高级计算机体系结构》课程实验：**基于计算机体系结构技术的矩阵乘法（GEMM）性能优化**。

本项目不调用 OpenBLAS 等现成库作为加速实现，而是在 C 中从朴素三重循环出发，逐步实现循环重排、缓存分块、数据打包、AVX2/FMA 寄存器分块微内核和 OpenMP 多线程，并通过统一基准程序比较各变体在不同矩阵规模下的性能。

## 基本原理

GEMM 的数学形式为 `C = A × B`。对 n×n 方阵，浮点运算量为 `2n³`；若 A、B、C 各只从主存读取一次，理想访存量为 `12n²` 字节，算术强度约为 `n/6` FLOP/Byte。

朴素 `i-j-k` 实现虽然计算量不变，但最内层对 k 归约时会按列访问行优先存储的 B，步长为 N。这会导致缓存行利用率低、硬件预取困难，并在矩阵规模超过 L2/L3 后迅速退化为访存受限。Roofline 模型因此把性能上界写成峰值算力与“算术强度 × 内存带宽”两者的较小值。

本实验沿以下技术链展开：

1. **循环重排**：把 `i-j-k` 改为 `i-k-j`，让最内层连续访问 B 和 C 的行。
2. **缓存分块**：把 A、B、C 的活动区域限制在 L1/L2/L3 容量内，提高块内复用。
3. **数据打包**：把跨行的 A/B 面板复制为连续、对齐的临时区域，便于顺序读取和 SIMD 载入。
4. **寄存器分块 + SIMD**：用 8×8 微内核和 AVX2/FMA，把标量乘加提升为 8 个 FP32 lane 的向量乘加。
5. **多线程**：用 OpenMP 按 C 的行块划分任务，利用多物理核并行。

这些技术分别针对访存局部性、缓存容量、数据布局、单核算力和线程级并行，单项收益受其瓶颈层级限制，因此还需要组合优化与消融实验。

## 实验内容

| 编号 | 变体                     | 核心思想                      | 主要考察             |
| ---- | ------------------------ | ----------------------------- | -------------------- |
| T0   | 朴素 `i-j-k`           | 三重循环基线                  | 建立性能基准         |
| T1   | `i-k-j` 循环重排       | 改善 B、C 的访问连续性        | 访存顺序的影响       |
| T2   | 仅 i/j 分块，`k_b = K` | 不合理分块对照                | 分块参数与访问布局   |
| T3   | 三维缓存分块             | 对 i、j、k 三个方向分块       | 缓存容量与块内复用   |
| T4   | 分块 + 数据打包          | A/B 面板连续化                | 数据布局与打包成本   |
| T5   | 寄存器分块 + AVX2/FMA    | 8×8 微内核                   | 单核算力与指令级并行 |
| T6   | OpenMP 行并行            | 按 C 的行块划分线程           | 线程扩展与共享资源   |
| best | 组合优化                 | 分块 + 打包 + 微内核 + OpenMP | 多技术协同           |

实验矩阵覆盖 `n = 128, 256, 512, 1024, 2048, 3072, 4096` 七个规模，分为四组：

| 实验组         | 内容                                                   |
| -------------- | ------------------------------------------------------ |
| 单一技术评估   | T0–T6 分别与朴素基线比较，观察加速比随 n 的变化       |
| 矩阵规模影响   | 固定变体扫描不同 n，分析 L2/L3/DRAM 容量转折           |
| 组合优化与消融 | 按 T0 → T1 → T3 → T4 → best 逐层叠加，并做消融对照 |
| 参数扫描       | best 的分块大小扫描，以及 T6 的 1/2/4/8 线程扩展       |

## 实验结果

下表列出 `n = 4096` 时主要变体的结果。完整数据表和分析见 [report/report.md](report/report.md)。

| 变体               |      时间 |  GFLOPS |  相对 T0 |
| ------------------ | --------: | ------: | -------: |
| T0 朴素            | 571.525 s |   0.240 |   1.00× |
| T1 `i-k-j`       |  15.472 s |   8.883 |  36.94× |
| T2 不合理 i/j 分块 |  45.575 s |   3.016 |  12.54× |
| T3 三维分块        |   8.638 s |  15.911 |  66.17× |
| T4 分块 + 打包     |   5.136 s |  26.760 | 111.28× |
| T5 仅 SIMD         |  14.920 s |   9.212 |  38.31× |
| T6 OpenMP 4T       |   5.870 s |  23.415 |  97.37× |
| best 64³/4T       |   1.252 s | 109.773 | 456.48× |

主要结论：

- T1 是所有单一技术中收益最直接的一步，说明朴素实现的首要问题是 B 的跨步访问。
- T2 在所有规模都慢于 T1，说明“分块”不是无条件收益，块参数必须匹配访问布局。
- T3/T4 在大矩阵上开始明显有效，数据打包是连接分块与 SIMD 微内核的关键环节。
- T5 单独使用时在小矩阵上表现很好，但大矩阵上仍受重复扫描和跨步访问限制。
- best 的默认 64³/4T 配置最稳健；128³/4T 在 `n = 4096` 达到 130.02 GFLOPS、540.68×，是本组最好观测值。
- 全部 16 个实验标签、1354 行数据均通过正确性阈值和 GFLOPS 一致性检查。

## 快速开始

```bash
cd gemm-lab
make

# 单个变体
./bench --variant naive --n 512 --reps 3
./bench --variant best  --n 1024 --reps 3 --threads 4

# 从已有原始数据重新生成汇总表、校验并绘图
python3 merge_data.py
python3 check_final.py
python3 plot_final.py
```

`./bench --help` 可查看全部参数。`run_all.sh` 用于批量运行基础变体扫描；全量实验耗时较长，日常复现不需要重跑所有数据。

`merge_data.py`、`check_final.py` 和 `plot_final.py` 依赖本地 `gemm-lab/data/*.csv`；CSV 不随仓库上传，重新生成这些文件需要先运行实验。

依赖：gcc（支持 OpenMP）、GNU Make、Python 3 + matplotlib。OpenBLAS、valgrind 可选；本实验未使用 cmake。

## 测量与正确性

- 统一编译选项：`-O3 -march=native -fopenmp -std=gnu11 -Wall -Wextra`。
- 所有变体采用 beta = 0 语义；C 在计时区外清零，清零时间不计入。
- 热身 2 次，重复次数自适应，取中位数；使用 `clock_gettime(CLOCK_MONOTONIC)` 计时。
- 每个变体先与双精度参考结果比对，未通过正确性阈值的结果不作为性能结论上报。
- 原始测量保存在本地 `gemm-lab/data/` 的 CSV 中，CSV 不随仓库上传；图表由脚本生成，不手工修改数据。
